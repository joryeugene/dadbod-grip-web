# Version 3.10.1

Version 3.10.1 closes process-argument leaks around AI providers and the remaining database clients. Existing AI settings and database URLs continue to work.

## AI requests stay out of process arguments

Anthropic and OpenAI headers, Gemini's key-bearing URL, provider URLs, prompts, schema context, existing SQL, and JSON request bodies now travel through `curl --config -` on standard input. When `ai.api_key` uses `cmd:...`, Dadbod Grip sends the shell program through shell standard input instead of a command argument.

API failures retain only a short error type such as `invalid_request_error`, and curl failures retain only the exit code. Dadbod Grip does not repeat remote error text or request content.

## Database statements use standard input

PostgreSQL, MySQL, MariaDB, SQLite, and SQL Server now receive their supported statements through standard input. PostgreSQL preserves URI options in a password-free, invocation-scoped libpq service file while its password remains in `PGPASSWORD`. SQL Server's seed workflow uses `SQLCMDPASSWORD` instead of a password argument.

DuckDB queries and attachment declarations already moved to standard input in [Version 3.10.0](v3.10.0).

These changes keep sensitive content out of `argv`. They do not hide environment variables or temporary files from other processes running as the same operating-system user.

## Contributors can check the attached layout

`just e2e-visual` opens a real tmux-backed Neovim UI and checks the attached workspace at narrow, default, and wide terminal sizes. Run it from the plugin repository before merging layout changes.

## Upgrade notes

No configuration migration is required. Existing provider settings, command-backed API keys, and database connection URLs continue to work.

Read the [v3.10.1 release on GitHub](https://github.com/joryeugene/dadbod-grip.nvim/releases/tag/v3.10.1).
