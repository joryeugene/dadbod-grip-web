# Version 3.10.0

Version 3.10.0 keeps database URLs out of saved queries, keeps DuckDB SQL out of process arguments, and prevents a failed export from replacing its destination with partial output. It also waits to draw the workspace until the initial schema is ready.

## Saved queries no longer store connection URLs

Persisted connections receive stable opaque IDs, and new query files use `-- grip:connection=<id>`. Renaming, promoting, deduplicating, or editing a connection preserves its ID. An unpersisted connection produces an unbound query and asks you to save the connection before binding it.

Legacy `-- grip:url=` files remain readable when the URL is templated or credential-free. Dadbod Grip removes credential-bearing legacy metadata from the editor and never auto-connects it. The next explicit save converts a resolvable legacy binding to an ID.

## DuckDB keeps SQL and credentials out of process arguments

DuckDB queries, mutations, schema requests, attachment validation, and attachment declarations now travel through standard input. Credentialed PostgreSQL and MySQL attachments use temporary, invocation-scoped DuckDB secrets. Dadbod Grip does not create persistent DuckDB secrets.

## Exports have an explicit scope

Clipboard and file exports now ask for the current page or all matching rows before asking for a format. All-row exports preserve filters and sorting while removing pagination. Clipboard output is capped at 100,000 rows, exports above 10,000 rows require confirmation, and file output uses a same-directory temporary file followed by an atomic rename.

## Connection startup waits for the schema

`setup({ open_sidebar = false })` opens directly into the main workspace while keeping the schema sidebar available on demand. The sidebar clamps when the terminal shrinks without automatically growing a width that you deliberately made narrower. Connection startup preloads the schema before drawing the finished workspace, and requery operations keep their loading indicator until the grid is ready.

## SQL Server, MariaDB, and files follow one routing path

SQL Server validates server certificates by default and accepts `encrypt`, `trust_server_certificate`, and `server_certificate` options on both `sqlserver://` and `mssql://` URLs. MariaDB schema labels remove integer display widths without losing modifiers such as `unsigned`.

A shared registry now routes Parquet, CSV, TSV, JSON, NDJSON, JSONL, XLSX, ORC, Arrow, and IPC files consistently through startup, connection discovery, and schema inspection.

## Checkhealth reports sqlcmd and Ollama

`:checkhealth dadbod-grip` now checks `sqlcmd` with the other database clients. An installed Ollama executable satisfies the optional AI-provider check without requiring a cloud API key.

## Upgrade notes

- Existing `connections.json` files remain readable, and IDs are assigned lazily.
- Existing saved queries remain readable under the legacy safety rules above.
- `open_sidebar` defaults to `true`, so existing layouts do not change unless you opt out.
- Existing export commands and keymaps remain the same; only the scope prompt is new.
- No new runtime dependency is required.
